# HUD 性能基准

运行 `npm run bench`。直接执行 `node scripts/benchmark-hud.mjs --build /absolute/path/dist --iterations 1000 --file-mib 32` 可对比独立构建。仅生成临时日志，不连接用户 tmux 或 Codex 服务；结束后删除临时文件。输出 JSON 包含每帧耗时、CPU、RSS、stdout 写入次数、子进程调用次数，以及四个长日志读取器的冷读、未变化复读和事件循环延迟。

2026-09-26 本机 Node v24.21.0，同一 fixture、140 列、每场景 1000 次，原提交 `c4e0697` 对比当前修复。原提交在临时目录构建，未切换或修改工作区。

四个读取器同时读取 32 MiB 日志：冷读 257 → 251 ms；RSS 均约 118 MiB；未变化复读 0.06 → 0.11 ms，处于极短采样区间，不据此宣称进退。事件循环 p95 12.09 → 11.98 ms。渲染改进来自复用准备好的布局计算高度，避免整帧格式化两遍。

这些是离线单次基准，不能换算成整个 HUD 的 CPU 或系统内存降幅。改动前四个实机 HUD 的 10.35 秒采样：每进程约占单核 0.39%–0.68%，RSS 之和约 259 MiB（含共享内存）。

行为门槛由回归测试约束：65 MiB 未读积压应分批前进到 EOF、坏记录之后继续读取、未变化日志直接复用缓存、真实按键/重载保持主 pane 存活。性能数字用于后续同机对照，不用脆弱的微秒级 CI 阈值代替行为验证。
