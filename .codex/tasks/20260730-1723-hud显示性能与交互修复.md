# codex-hud 显示、性能与交互修复

## 目标

在不改变现有 tmux/Codex 会话生命周期语义的前提下，修复 rollout 增量解析错误，降低 HUD 热路径 I/O，提升固定高度下的信息优先级、状态准确性和诊断能力。

## 不变量

- detach 或终端关闭后，既有 Codex/tmux 会话继续存活并可重连。
- 不改动 `/new`、`/resume`、client attach gate、主 pane 生命周期和默认 tmux server。
- 不写用户全局配置，不操作真实活跃 tmux 会话。
- 不创建 Git commit；不覆盖仓库外或用户无关修改。
- `/Users/zyb/.codex/skills` 是 Codex skill 权威目录；其他 Agent skill 仅在 verbose/诊断语义中单独统计。

## 阶段

- [x] 记录类型、协议与测试基线。
- [x] 修复 plan 增量保留、`update_plan` 兼容及半行 JSONL offset。
- [x] 解析 turn lifecycle、rate limit、tool search 和未知协议计数。
- [x] 将 Git/项目资产等慢采集改为异步缓存，渲染周期只读快照。
- [x] 优化 agent/overview 的增量采集。
- [x] 调整固定高度信息优先级、状态与 freshness、Unicode 宽度。
- [x] 修正 Node 与测试脚本契约，增加 doctor/reload 等低风险管理能力。
- [x] 执行类型检查、单元、集成、隔离 E2E、性能与对抗性复审。

## 主要风险

- rollout 协议同时存在旧式 `event_msg` 与新式 tool call，需要保持向后兼容。
- 缓存可能把真实错误伪装成旧数据，必须显示 stale/error 状态。
- 更快的渲染时钟不能扩大 I/O 频率。
- CMUX capability 传播与通知授权耦合；本机 event-time router 必须从 tmux session 读取当前 capability，缺失时会按安全策略 fail closed。
- 自动高度或全局 tmux binding 会影响用户布局，默认不启用。

### 当前协议实测

对本机最新 rollout 只读解析：`parsed=true`、`totalTools=320`、`planSteps=6`、`phase=running-tool`、`rateLimits=true`、`unknownProtocolRecords=0`。未输出消息正文、工具参数或 rollout 路径。

### 性能前后

- Git：旧热路径每秒执行 5 个同步 Git 子进程；新路径每 5 秒最多 1 个异步 porcelain-v2 子进程，默认子进程频率从约 300/min 降到 12/min（25 倍）。
- 配置/项目资产：从每次渲染同步读取，改为 Worker 线程 + 60 秒 TTL + 配置事件强制刷新；渲染函数只组装内存快照。
- Overview：只在概览模式刷新，5 秒 TTL，并按文件 size 复用增量 parser；单 Session 模式不再后台扫描。
- Agent：未变化的 root/child rollout 只做 `stat`，不再重复 open/read；仍保留归档迁移与错误恢复。
- 渲染时钟：活动 500 ms、空闲 1500 ms、未绑定 2500 ms；频率变化不扩大 I/O 频率。
- tmux scrollback：移除 session-wide `200000`，HUD pane 默认 `10000`，主 pane 保留继承值。

### 对抗性复审结论

- 并行工具最后一个 output 跨增量 batch 时，turn 能从 `running-tool` 正确回到 `thinking`；旧 turn 的迟到 complete 不会结束新 turn。
- 损坏或错误类型的 `config.toml` 保留最后成功配置，同时继续采集项目资产，并显示 `config error`。
- Git 操作错误进入 collector health；“不在 Git 仓库中”仍是有效 fresh 快照。
- CMUX capability 保持 session-scoped，并与 workspace/surface/socket path 一起覆盖 tmux server 的陈旧环境；不进入 pane command、`send-keys` 或 HUD 输出。隔离真实 tmux 验证 Codex pane 与 event-time router 均能从 session 读取同一当前值。
- 曾尝试改为仅由 Codex pane 导入一次性 capability 文件，但这违反了本机 `cmux-live-tmux-context.sh` 的事件时读取契约，导致 Running/Idle、正文和通知全部 fail closed；该改动已撤销，并新增 session 读取回归断言。
- `--toggle-mode` 只沿目标 HUD pane 的进程树定位 `dist/index.js` Node 进程；新式直接 Node pane 和旧式 shell→Node pane 均通过隔离测试。
- 默认工具详情不显示执行命令；动态 model/project/plan/agent/session 文本会去除终端控制与 bidi 序列。
- 未触碰默认 tmux server 或任何活跃 Codex pane；所有真实 tmux 用例使用独立 `TMUX_TMPDIR`。

### 保留风险

- 为保持 `/new`、`/resume` 和 pane/process 绑定语义，`SessionFinder` 的完整 tmux/ps/sqlite 探测仍是主线程上每 5 秒节流执行；极端负载下仍可能造成短暂停顿。
- Agent 树仍需每秒对每个活跃节点执行一次 `stat`，复杂度为 O(N)，但文件不变时不会读取内容。
- 概览模式首次扫描当天/前一天目录仍在主线程发起；已限制为仅概览模式且 5 秒缓存，没有改写高风险的 Session 发现契约。
- 本轮未对真实活跃 HUD 执行 `--reload`，避免打断用户；现有 pane 需要用户显式 reload 或新开 Session 才会加载新构建。
- 在错误 capability 方案期间启动的 Codex 进程没有注入 CMUX hooks；仅 reload HUD pane 无法补装进程启动参数，需要在修复后新启动或 resume Codex。
