# exec 工具详情显示

## 目标

- 修正 `exec_command` 非零退出码仍显示成功的问题。
- 区分工具调用完成、底层进程退出和底层进程转入后台 session。
- 在默认 5 行 HUD 内显示当前执行操作与最近结果的安全摘要。
- 为 `write_stdin`、`apply_patch` 提供有意义但不泄露原始内容的摘要。

## 边界

- 不修改 tmux 生命周期、SessionFinder、Hook 统计或分支同步逻辑。
- 不执行或 `eval` `custom_tool_call: exec` 的 JavaScript 源码。
- 不保存或显示原始 stdout/stderr。
- 不纳入既有 `.codex/visualizations/`。

## 主要风险

- 命令参数可能包含 token、密码、Authorization header 或带凭据 URL。
- Codex CLI 的 direct/custom 工具事件和文本输出包装可能继续变化。
- 默认 HUD 只有 5 行，新增物理行会挤掉 Plan/Subagent。
- 长任务返回 session ID 时，工具 API 已结束但底层进程仍在运行。

## 实施步骤

1. 扩展 `ToolCall` 的安全摘要和结构化执行结果。
2. 解析 direct function arguments、custom exec 单工具字面量、patch 文件头。
3. 仅从输出包装头解析退出码、wall time 和 session ID。
4. 改造工具活动行为单行、宽度感知的详细摘要。
5. 补充解析、脱敏、错误状态、后台状态和宽度测试。
6. 回放当前真实 rollout，并运行构建、单元、集成与 E2E 回归。

## 验收

- `exit 0`、`exit 1`、后台 session、未知包装分别得到正确结构化结果。
- stdout 内伪造的状态文本不会影响包装头解析。
- 命令摘要移除控制字符并对常见 secret 形式脱敏。
- custom exec 多工具或动态输入保持保守降级，不重复计数。
- 80/120/146 列输出不越界，默认仍只占一行工具活动空间。
- 当前真实 rollout 回放能识别非零退出结果。
- 构建、相关单元测试、集成测试和安全隔离 E2E 通过。

## 完成记录

- `ToolCall` 已增加脱敏摘要、工作目录和结构化执行结果。
- direct 输出只解析 `Chunk ID` 后、`Output:` 前的元数据包装；stdout 内伪状态不会参与判断。
- `exec_command` 已区分 `exit 0`、非零退出、后台 session 和未知包装。
- `write_stdin` 已区分 poll/send 摘要，`apply_patch` 已显示动作与文件摘要。
- custom exec 只解析唯一且为 JSON 字面量的参数；多工具调用保持单个 `exec` 并显示静态工具集合。
- 工具活动仍为单行，运行中调用、最近错误、耗时、退出码/session 和总数按宽度裁剪。
