# HUD 自适应布局

## 目标

解决默认固定 5 行时目录、Session 和活动信息经常被裁掉的问题，同时避免 HUD 无上限侵占 Codex 主窗格。

## 已确认事实

- 默认高度由 `bin/codex-hud:resolve_hud_height` 固定为 5。
- `CODEX_HUD_HEIGHT_AUTO` 默认关闭，现有 resize helper 只按宽度加行。
- 展开布局把 Session/Dir 放在计划和工具历史之后，固定高度下最先被裁掉。
- 渲染器已经有 viewport 上限和 `+N hidden` 指示，无需取消安全裁剪。

## 实现边界

- 默认高度按终端高度的 `1/6` 计算，并限制为 5–12 行。
- 窄终端默认增加最多 3 行；显式 `CODEX_HUD_HEIGHT` 仍是固定高度，除非明确设置 `CODEX_HUD_HEIGHT_AUTO=1`。
- resize hook 重新计算尺寸，不在渲染循环中启动 tmux 子进程。
- attach/`--reload` 会为旧 Session 写入新高度策略，不要求先手工删除 Session。
- Session/Dir 提前到计划和已完成工具历史之前；路径按终端单元格宽度保留尾部。
- 不改 CMUX、hooks、SessionFinder、安装升级流程或默认 tmux server。

## 验证

- TypeScript typecheck/build 和渲染单元测试。
- 默认/显式高度、宽度和窗口高度变化的 fake-tmux 集成测试。
- 全量 `npm test`。
- 运行任何真实 tmux 测试前先静态检查 socket 隔离；不操作默认 tmux server。

## 验证结果

- `npm test` 全量通过：28 个 unit 文件、26 个 integration 文件。
- 默认高度覆盖 24/60/120 行终端、窄 pane、关闭自动宽度、显式固定和显式 auto。
- resize 覆盖纵向重算、横向补偿、5–12 上限、copy-mode 和焦点保护。
- 隔离 tmux 的 `--reload` 证明旧 Session 会迁移到新高度策略。
- 默认 tmux 测试前后 PID 与 Session 指纹一致。
- 当前 `/Users/zyb/Desktop/prj` Session 已定向 reload：窗口 46 行时 HUD 从 5 行变为 7 行，主 pane PID 不变，`Dir:` 可见且无隐藏行。
